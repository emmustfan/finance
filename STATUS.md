# Этап 1. Карточки документов

Работает создание зашифрованного архива, добавление карточек с PDF и бумажным адресом, поиск по названию, номеру, человеку, типу, меткам и папке. Можно добавить карточку только с адресом или только с PDF. Копия восстанавливает карточки вместе с вложениями. Тестовые личные архивы поддерживают изменение тегов и добавление карточек, включая архивы из ранних версий.

Теги можно задать при добавлении документа и поменять в существующей карточке. Список тегов строится по открытому архиву. Выбранный тег сужает текстовый поиск. Формат сохранённых архивов поддерживает это обновление без преобразования файлов.

В открытом архиве можно изменять поля, теги и создавать копию без повторного ввода пароля. Архив назначает карточкам последовательные номера. Поле «Тип» предлагает стандартные варианты и значения из карточек открытого архива.

Автоматические тесты на Linux проверяют поиск, восстановление карточек и вложений после удаления исходных файлов, пароль при открытии, редактирование старых архивов и отказ при попытке перезаписи из устаревшего окна. Проверены фильтрация по точному тегу, сохранение тегов и номеров при редактировании, собственные типы документов и резервные копии. В карточке можно хранить PDF и несколько фото JPEG или PNG. Опись собирает документы из выбранной бумажной папки и сортирует их по разделу и номеру в папке. Ручная проверка этапа 1 на Mac описана в [README.md](README.md). Совместная запись остаётся открытой.

Интерфейс на Qt проверен в Linux. Проверены добавление PDF и фото, переключение предпросмотра, добавление и удаление тегов, фильтрация по щелчку на теге, поиск по номеру, создание копии, закрытие архива и переход из описи к карточке. Опись проверена по сгенерированному PDF. При проверке печати фотографии подтверждена передача одностраничного PDF команде печати. Использовались автоматизированные ответы файловых диалогов и парольного запроса. Оформление, системные диалоги и физическая печать на macOS ещё не проверены.

# Этап 0

Прототип создает зашифрованный тестовый архив, показывает PDF, отправляет его в системную очередь печати и восстанавливает архив из проверенной копии.

На облачном Debian пройдены три теста. Проверены отдельные пароли и права нового файла `0600`, отказ при повреждении копии, отказ при попытке перезаписать файл и восстановление после удаления источника. PDFium прочитал текст и отрисовал страницу из восстановленного архива. Синтаксис скрипта сборки проверен Bash. Из облака загружены бинарные зависимости для Python 3.12 на macOS 13 для Intel и Apple Silicon.

Пользователь подтвердил запуск на семейном Mac с Python 3.14.10. Остальные проверки этапа 0 еще открыты. Нужны версия и архитектура macOS, сборка и установка `.pkg`, реальная проверка из двух учетных записей, печать и восстановление с внешнего носителя без сети. После приемки следует закрыть решение о стеке в [DECISIONS.md](DECISIONS.md) и перейти к этапу 1 из [SPEC.md](SPEC.md).

## Проверка на семейном Mac

Работайте с тестовыми архивами, которые создает само приложение. Для сборки нужны macOS 13 или новее и Python 3.12, а для загрузки зависимостей нужен интернет. Запишите вывод `sw_vers -productVersion` и `uname -m`. Из корня репозитория выполните:

```bash
bash prototype/build-macos.sh
open prototype/dist/FinanceArchive.pkg
```

После установки запустите «FinanceArchive» из «Программы». Для теста установки без сети оставьте собранный пакет локально и отключите сеть до открытия пакета. Для печати без интернета подойдет USB-принтер или локальная сеть с отключенным выходом в интернет.

1. Под первой учетной записью создайте `family.fvault` и `personal.fvault` в домашнем каталоге. Задайте разные тестовые пароли. Ожидается, что каждый архив открывается своим паролем и показывает страницу «Family archive - test PDF».
2. Из терминала первой учетной записи с правами администратора создайте тестовую группу и разместите семейный файл. Впишите короткие имена двух реальных учетных записей вместо `firstuser` и `seconduser`. Команды предполагают, что группа и каталог `financearchive-test` еще не существуют.

   ```bash
   sudo dseditgroup -o create financearchive-test
   sudo dseditgroup -o edit -a firstuser -t user financearchive-test
   sudo dseditgroup -o edit -a seconduser -t user financearchive-test
   sudo install -d -o root -g financearchive-test -m 0750 /Users/Shared/financearchive-test
   sudo install -o root -g financearchive-test -m 0640 \
     "$HOME/family.fvault" /Users/Shared/financearchive-test/family.fvault
   mkdir -m 0700 "$HOME/financearchive-private-test"
   mv "$HOME/personal.fvault" "$HOME/financearchive-private-test/"
   ```

3. Выйдите из обеих учетных записей и войдите в них по очереди, чтобы обновилось членство в группе. Под каждой откройте `/Users/Shared/financearchive-test/family.fvault` в приложении. Ожидается, что оба пользователя видят PDF. Под второй учетной записью выполните `head -c 1 /Users/firstuser/financearchive-private-test/personal.fvault`. Ожидается отказ в доступе. Под первой учетной записью попробуйте открыть личный архив с семейным паролем. Ожидается отказ в расшифровке.
4. В macOS назначьте принтер по умолчанию. Откройте семейный архив, нажмите «Печать» и подтвердите. Ожидается одно задание в очереди и одна страница с тестовым текстом на принтере.
5. При открытом семейном архиве нажмите «Создать копию» и сохраните ее на внешнем диске. Во второй учетной записи, без интернета, выберите «Восстановить из копии» и сохраните архив под новым именем в своем домашнем каталоге. Ожидается, что PDF сразу появится и восстановленный архив удастся открыть повторно. Повторите восстановление в то же имя. Ожидается отказ с сохранением существующего файла.

Для перепроверки логики в среде разработки с Python 3.12:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --only-binary=:all: -r prototype/requirements.txt
.venv/bin/python -m unittest discover -s prototype -v
```
