# Решения этапа 0

| Вопрос | Решение |
| --- | --- |
| Целевая ОС | macOS. Версию и архитектуру семейного Mac уточняем перед проверкой установщика. |
| Стек для проверки | Прототип на Python, PySide6 (Qt), PDFium и cryptography. Интерфейс переведён с Tk на Qt для настраиваемого оформления и интерактивных тегов. Выбор рабочего хранилища остаётся открытым. |
| Семейный доступ | Отдельные учетные записи macOS и отдельная локальная группа. Администратор назначает группе права на общий каталог. Семейный файл и его блокировка получают доступ группы, а при записи проверяется версия. Оба участника вводят общий пароль. Личные архивы и архивы ИП создаются с правами владельца. |
| Личный доступ | Тестовый архив лежит в приватном каталоге владельца и открывается отдельным паролем. Прототип проверяет границы обычных учетных записей ОС. Администратор Mac может изменять права, поэтому шифрование и отдельный пароль нужны даже при корректных правах на файлы. |
| Шифрование | AES-256-GCM защищает содержимое и заголовок. Scrypt выводит ключ из пароля и соли архива. Ключ используется в памяти до закрытия или смены архива. Для каждой записи генерируется новый nonce. Пароль запрашивается при открытии и не сохраняется. |
| Копия и восстановление | Копия содержит те же зашифрованные байты. Перед копированием проверяется тег целостности. Восстановление создает отдельный файл и открывает вложение. Пароль нужен тот же, что у исходного архива, его хранят отдельно от носителя. Формат рабочего архива с несколькими вложениями и базой предстоит определить. |
| PDF и печать | PDFium отображает страницы из памяти. На Mac печать передает PDF по stdin в системную команду lp. Расшифрованный PDF не записывается приложением в отдельный файл. Очередь CUPS может хранить данные задания. |
| Установщик | Сборка без подписи Developer ID и нотарификации предназначена для локальной приемки на Mac, где ее собрали. Скрипт упаковывает среду Python в приложение и создает .pkg. Подписанный установщик для распространения остается открытым решением. |

## Контейнер документов для первого сценария этапа 1

Контейнер v2 хранит карточки и вложенные PDF одним зашифрованным файлом. Обновления в локальном архиве владельца выполняются с блокировкой и проверкой версии перед атомарной заменой файла. Контейнер v1 открывается как демонстрационный документ. Первая правка личного архива v1 сохраняет документ и переводит файл в v2. Семейный архив, созданный в папке группы, поддерживает запись её участников. Вложения до 20 МиБ, закодированные карточки и вложения вместе до 64 МиБ. Это промежуточный формат для проверки сценария. Выбор рабочего хранилища и проверка семейной записи остаются открытыми.

Номера карточек уникальны внутри архива. Старые карточки получают номера по порядку при чтении и сохраняют их при следующей записи. Прежнее поле номера относится к бумажному или электронному оригиналу. Тип выбирается из стандартного списка либо вводится вручную. Нет необходимости вести отдельный справочник для типов, которые уже используются в карточках архива.

Карточка может хранить один PDF и несколько исходных файлов JPEG или PNG. Фото сохраняются в том же зашифрованном контейнере, каждое до 12 МиБ и 50 мегапикселей. Запись фото добавляет поле в карточку, которое требует актуальной версии приложения. Опись вычисляется из заполненных полей шкафа, папки, раздела и номера в папке. Папки с одинаковым названием в разных шкафах имеют отдельные описи.

Реестр находится в том же зашифрованном контейнере, что и документы. Ссылки используют номера карточек внутри этого архива. Известные суммы хранятся целыми числами с двумя десятичными знаками и сопровождаются датой и кодом валюты. Сводка группирует суммы по категории и валюте и берёт только действующие карточки. KeePassXC хранит пароли, а архив хранит текстовый путь к записи.

Журнал использует номер карточки счёта из реестра. Начальная сумма относится к концу дня. Последующие операции складываются в валюте счёта. Вычисленная сумма заменяет ручную оценку в сводке. Пакет CSV записывается одной операцией архива. Для точного повтора используется хеш файла по счёту, для ID банка действует область счёта. Совпадения без ID требуют решения пользователя, если по дате, сумме и описанию возможен повтор.

Переводы и категории ссылаются на неизменяемый номер проведённой операции. Подтверждение не создаёт повторных банковских движений. В отчёте разница между связанным списанием и зачислением является комиссией, указанной при подтверждении. Календарь ежемесячных платежей сопоставляет план с проведённой записью. Фонды ведут отдельный журнал резервирования. Шаблон считается в порядке правил одной валюты, а оплата из фонда ссылается на уже проведённое списание.
